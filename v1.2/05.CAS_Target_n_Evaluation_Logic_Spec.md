# 05. CAS_Target_n_Evaluation_Logic_Spec

## 1. Document Purpose

04문서의 계산 엔진이 산출한 비용 결과를, **목표(Target) 대비 달성 여부(Evaluation)로 판단**하는 규칙을 정한다.

다시 말해, 숫자를 GREEN/YELLOW/RED 판정으로 바꾸는 기준이다. 평가 결과는 이 문서의 로직으로만 만들어진다.

---

## 2. Core Evaluation Philosophy

### 2.1 View-dependent Evaluation

* CAS의 모든 목표와 평가는 **View(View Mode)** 에 종속된다.
* 동일한 Snapshot에 대해서도 View에 따라 **서로 다른 목표와 평가 결과**가 동시에 존재할 수 있다.

CAS는 다음 두 가지 View를 기본으로 지원한다.

| View Code | Description               |
| --------- | ------------------------- |
| INIT      | 초기년(Initial Year) 기준 View |
| AVG5      | 5년 평균(5Y Average) 기준 View |

---

### 2.2 Parallel Judgement Principle

* INIT View와 AVG5 View의 평가 결과는 **병렬적으로 공존**한다.
* 하나의 View에서의 미달성은 다른 View의 달성 여부에 영향을 주지 않는다.
* CAS는 복수 View의 평가 결과를 **통합·종합·평균하지 않는다**.

---

## 3. Target Definition Model

### 3.1 Target Scope

Target은 다음의 조합 단위로 정의된다.

```
Target = Vehicle × Stage × View × Metric
```

* Vehicle: 개별 차종 (MVP에서는 Vehicle Group이 아닌 개별 Vehicle 단위)
* Stage: 비용 결정 단계
* View: INIT / AVG5
* Metric: 평가 대상 지표

> **v1.1 구현 반영:** MVP 단계에서 Target은 `Vehicle Group`이 아닌 개별 `Vehicle` 단위로 정의. 향후 Vehicle Group 기반 일괄 Target 설정은 Phase 9 이후 확장 가능.

**OWL Representation:**

Target은 `cas:Target` 클래스의 개체로 표현되며, 다음 프로퍼티로 평가 맥락을 고정한다.

* `cas:targetForVehicle` → `cas:Vehicle`
* `cas:targetAtStage` → `cas:Stage`
* `cas:targetView` → `cas:ViewMode` (`cas:INIT_VIEW` / `cas:AVG5_VIEW`)
* `cas:targetMetric` → `xsd:string` (e.g., `"COST_RATIO"`)
* `cas:targetValue` → `xsd:decimal`
* `cas:warningThreshold` → `xsd:decimal`
* `cas:criticalThreshold` → `xsd:decimal`

Target 개체는 Snapshot 생성 시점에 Triple Store에 동기화되며, 이후 변경 불가하다 (10 §6.1 참조).

---

### 3.2 Target Metric Set

CAS v1에서 기본으로 평가 대상이 되는 Metric은 다음과 같다.

| Metric Code           | Description | Target Value | Scenario |
| --------------------- | ----------- | ------------ | -------- |
| COST_OF_SALES_RATIO   | 매출원가율       | 80% (0.80)   | 1안 (가혹조건) |
| COST_RATIO            | 총비용율        | 100% (1.00)  | 2안 (완화조건) |

> **v1.1 구현 반영 (2안 구조):** 기존 분석 스프레드시트에서 확인된 2안 병행 평가 구조를 반영.
> - **1안:** 매출원가율(Cost of Sales Ratio) ≤ 80% 달성 — 가혹 조건
> - **2안:** 총비용율(Total Cost Ratio) ≤ 100% 달성 — 완화 조건
> - 각 안별로 재료비/조립비/물류비/포장비 목표가를 자동 역산 (04 §4.7.4)
> - 1안 또는 2안 미달성 시 리포트 발송 트리거

※ 향후 확장 Metric은 본 문서 개정으로만 추가 가능하다.

---

### 3.3 Target Value Definition

Target 값은 다음 속성을 가진다.

| Field              | Description       |
| ------------------ | ----------------- |
| target_value       | 기준 목표값 (예: 0.85)  |
| warning_threshold  | 경고 임계값 (예: +0.02) |
| critical_threshold | 위험 임계값 (예: +0.05) |

Target 값은 **per-unit 기준**으로 정의되며, 금액 기준 평가는 파생 계산 결과로만 사용된다.

---

## 4. Evaluation Logic

### 4.1 Base Comparison Rule

모든 평가는 아래 기본 규칙을 따른다.

```
Evaluation Base = Calculated Metric Value (Snapshot × View)
```

비교 기준은 해당 View에 정의된 Target Value이다.

---

### 4.2 Status Classification Rules

총비용율(COST_RATIO)에 대한 상태 분류 규칙은 다음과 같다.

| Status | Condition                                                          |
| ------ | ------------------------------------------------------------------ |
| GREEN  | metric_value ≤ target_value                                        |
| YELLOW | target_value < metric_value ≤ target_value + warning_threshold     |
| RED    | metric_value > target_value + warning_threshold                    |

※ Threshold 값은 Stage별로 상이할 수 있다.
※ warning_threshold ≤ critical_threshold 이어야 한다.
※ critical_threshold는 RED 상태 내에서 **긴급도 구분**(알림 강화 등)에 사용되며, GREEN/YELLOW/RED 상태 분류 경계는 target_value와 warning_threshold가 담당한다.

**SWRL Evaluation Rules:**

위 상태 분류는 SWRL 규칙으로 형식화되어 온톨로지 추론 엔진에서도 동일하게 판정된다.

* **SWRL-EVAL-001 (GREEN):** `cas:EvaluationResult(?e) ∧ cas:metricValue(?e, ?v) ∧ cas:targetValue(?e, ?t) ∧ swrlb:lessThanOrEqual(?v, ?t) → cas:evaluationStatus(?e, cas:GREEN)`
* **SWRL-EVAL-002 (YELLOW):** `cas:EvaluationResult(?e) ∧ cas:metricValue(?e, ?v) ∧ cas:targetValue(?e, ?t) ∧ cas:warningThreshold(?e, ?w) ∧ swrlb:greaterThan(?v, ?t) ∧ swrlb:add(?tw, ?t, ?w) ∧ swrlb:lessThanOrEqual(?v, ?tw) → cas:evaluationStatus(?e, cas:YELLOW)`
* **SWRL-EVAL-003 (RED):** `cas:EvaluationResult(?e) ∧ cas:metricValue(?e, ?v) ∧ cas:targetValue(?e, ?t) ∧ cas:warningThreshold(?e, ?w) ∧ swrlb:add(?tw, ?t, ?w) ∧ swrlb:greaterThan(?v, ?tw) → cas:evaluationStatus(?e, cas:RED)`

SWRL 평가 결과와 계산 엔진 평가 결과는 반드시 일치해야 한다. 불일치 시 BLOCKER 결함으로 처리한다 (10 §10 참조).

---

### 4.3 Evaluation Output

각 Evaluation 결과는 다음 정보를 반드시 포함한다.

* vehicle_id
* stage_code
* view_code (INIT / AVG5)
* metric_code
* metric_value
* target_value
* evaluation_status (GREEN / YELLOW / RED)
* evaluation_timestamp

각 Evaluation 결과는 `cas:EvaluationResult` 클래스의 OWL Individual로도 Triple Store에 기록된다. `cas:evaluatedInSnapshot`을 통해 해당 Snapshot과 연결되며, SWRL 추론에 의해 `cas:evaluationStatus`가 자동 추론된다 (10 §7.2 참조).

---

## 5. Stage-specific Target Rules

### 5.1 Bid Stage

* Bid Stage는 **평가 대상이 아니다**.
* Bid Snapshot은 모든 평가의 기준(anchor)으로만 사용된다.

이 제약은 SHACL `cas:BidNonEvaluableShape`가 온톨로지 레벨에서 잡아준다: `cas:BID_STAGE`를 참조하는 Snapshot에는 `cas:EvaluationResult` 개체를 만들 수 없다 (10 §6.6 참조).

---

### 5.2 Design Cost Review Stages

* 설계원가 1차~N차 Stage는 **모두 평가 대상**이다.
* Stage가 진행될수록 목표 달성 난이도가 완화될 수 있으나, 이는 Target 값 설정의 책임이다.

---

### 5.3 SOP & Post-SOP Stages

* SOP Stage는 최종 내부 판단 기준으로 사용된다.
* Post-SOP Stage는 **평가 결과는 생성되되, 경고/위험 알림 정책은 별도로 설정 가능**하다.

---

## 6. UI Representation Rules

* Evaluation Status는 **색상(GREEN/YELLOW/RED)** 으로 구분해서 표시한다.

* INIT / AVG5 View 전환 시:

  * 표시되는 Target
  * Evaluation Status
    가 동시에 전환되어야 한다.

* 복수 View의 평가 결과는 **동시에 병합 표시되지 않는다**.

---

## 7. Audit & Traceability

* 모든 Evaluation 결과는 Snapshot과 1:1로 연결된다.
* Target 변경 이력은 별도 로그로 관리되며, 기존 Snapshot의 평가 결과는 변경되지 않는다.
* 온톨로지 추론에 의한 평가 결과(`cas:EvaluationResult`)는 해당 Snapshot의 트리플 그래프에 포함되며, 추론 프로비넌스(적용된 SWRL 규칙 ID, 온톨로지 버전)가 메타데이터로 기록된다 (10 §9 참조).

---

## 8. Explicit Non-Scope

다음 항목은 CAS v1 평가 범위에 포함되지 않는다.

* View 간 평가 결과 통합
* 가중 평균 평가
* AI 기반 판단 보정

---

## 9. 주의사항

Evaluation은 Calculation 결과를 읽기만 하지, 고치지 않는다. SWRL 추론 결과와 계산 엔진 판정이 다르면 배포 차단(BLOCKER)이다.
