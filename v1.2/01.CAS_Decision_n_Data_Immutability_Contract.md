# 01. CAS_Decision_n_Data_Immutability_Contract

## 1. Document Purpose

CAS에서 다루는 데이터와 판단 결과에 대해 **누가 결정하는가(Decision Ownership)**와 **한 번 생성된 데이터를 바꿀 수 있는가(Data Immutability)**를 정한다.

이후의 데이터 모델, 계산 로직, API, UI, 운영 정책은 모두 이 문서의 원칙 안에서 설계되어야 한다.

---

## 2. Core Principles

### 2.1 Decision Ownership Principle

CAS에서 발생하는 모든 결과는 아래 세 범주 중 하나에 속해야 하며, 범주 간 책임은 혼합될 수 없다.

| Category       | Description                      | Owner                   | Ontology Classification                             |
| -------------- | -------------------------------- | ----------------------- | ---------------------------------------------------- |
| Fact           | 사용자가 입력하거나 외부 시스템으로부터 수집된 원본 데이터 | Human / External System | `cas:InputFact` (Asserted Triple)                    |
| Derived Value  | 규칙 기반 연산을 통해 산출된 수치 결과           | Rule Engine             | `cas:DerivedFact` (SWRL 추론에 의한 Inferred Triple)      |
| Interpretation | 결과에 대한 설명, 해석, 코멘트               | Human                   | `cas:Interpretation` (OWL Annotation, 추론 대상 아님)      |

※ LLM은 CAS v1에서 **어떠한 Category의 Owner도 아니다**.
※ 온톨로지 추론 엔진(SWRL)은 Rule Engine의 **형식 논리적 구현체**이며, 별도의 의사결정 주체가 아니다 (10 §7 참조).

---

### 2.2 Temporal Immutability Principle

CAS는 특정 시점의 판단이 이후 환경 변화로 인해 왜곡되는 것을 허용하지 않는다.

그래서 CAS는 주요 데이터를 모두 **Snapshot 단위로 고정**한다.

* Snapshot은 생성 이후 **수정·삭제·재계산이 불가**하다.
* Snapshot은 새로운 Snapshot으로만 대체될 수 있다.
* 모든 분석 결과는 반드시 특정 Snapshot을 참조해야 한다.

Snapshot 불변성은 두 겹으로 걸어 놓았다.

* **데이터베이스 수준**: PostgreSQL의 UPDATE/DELETE 제약
* **온톨로지 수준**: SHACL `cas:SnapshotImmutabilityShape`에 의한 트리플 수정 차단 (10 §6.1 참조)

---

## 3. Stage-based Snapshot Policy

### 3.1 Stage Definition

Stage란, 수주 이후 개발·양산 과정에서 비용이 결정되는 시점을 말한다. 각 Stage는 OWL Named Individual로 정의하고, `cas:stageOrder`로 순서를 잡는다 (10 §5.1 참조).

기본 Stage 체계는 다음과 같다.

1. Bid (수주) — `cas:BID_STAGE`
2. Design Cost Review – 1st (설계원가 1차) — `cas:DC1_STAGE`
3. Design Cost Review – 2nd (설계원가 2차) — `cas:DC2_STAGE`
4. Design Cost Review – 3rd (설계원가 3차) — `cas:DC3_STAGE`
5. SOP Initial Price (양산 초도가) — `cas:SOP_STAGE`
6. Post-SOP Design Change – Nth (양산 후 설변) — `cas:POST_SOP_STAGE`

※ Post-SOP Stage는 개수 및 시점이 사전에 고정되지 않는다.

---

### 3.2 Snapshot Creation Rule

* 각 Stage 진입 시점에 **Stage Snapshot**이 생성된다.
* Stage Snapshot은 해당 Stage에서의 모든 차종·품번 비용 구조를 포함한다.
* Snapshot 생성 이후:

  * 기존 Snapshot은 변경 불가
  * 다음 Stage Snapshot은 반드시 직전 Snapshot을 참조하여 생성된다.

Stage 전환 합법성은 SHACL `cas:StageTransitionShape`에 의해 검증된다: `cas:basedOnSnapshot`은 직전 `cas:stageOrder`를 가진 Stage의 Snapshot을 참조해야 한다 (10 §6.2 참조).

## 4. Data Mutability Matrix

| Data Type         | Example             | Mutability                   | Owner           | Ontology Enforcement                |
| ----------------- | ------------------- | ---------------------------- | --------------- | ----------------------------------- |
| Raw Input Data    | 품번 단가, Usage, Stage | Editable (Pre-Snapshot)      | Staff           | —                                   |
| Snapshot Data     | Stage별 비용 구조        | Immutable                    | System          | `cas:SnapshotImmutabilityShape`     |
| Reference Data    | 인건비, 환율             | Editable (Approval Required) | Staff → Manager | —                                   |
| Derived Metrics   | 제조원가율, 총비용율         | Immutable                    | Rule Engine     | SWRL 추론 결과 (Inferred Triple)        |
| Target Evaluation | 목표 달성 여부            | Immutable                    | Rule Engine     | SWRL 평가 규칙 + `cas:BidNonEvaluableShape` |
| Comment           | 마진 변동 사유            | Editable                     | Human           | OWL Annotation (추론 대상 아님)           |

---

## 5. Recalculation & Versioning Policy

* 모든 계산 로직은 버전 관리된다.
* 각 Snapshot에는 다음 메타데이터가 기록된다.

  * 적용된 계산 로직 버전 (`calculation_version`)
  * 적용된 기준 데이터 버전 (`reference_data_version`)
  * 적용된 온톨로지 스키마 버전 (`ontology_version`)
* 기준 데이터 변경은 **과거 Snapshot에 영향을 미치지 않는다**.
* 새로운 기준 데이터는 이후 생성되는 Snapshot에만 적용된다.
* 온톨로지 스키마 변경(SWRL 규칙 변경 포함)은 과거 Snapshot의 트리플에 영향을 미치지 않는다.

---

## 6. Human Intervention Boundary

* 사용자가 직접 할 수 있는 건 **Fact 입력과 Interpretation 작성**뿐이다.
* 사용자는 어떠한 경우에도 Derived Value 및 Evaluation Result를 직접 수정할 수 없다.
* 승인(Manager)은 데이터 변경이 아니라 **변경 요청의 승인 행위**로만 기록된다.

---

## 7. AI Usage Policy (Explicit Non-Usage)

* CAS v1은 LLM API를 사용하지 않는다.
* 자동 판단, 목표 설정, 평가 결과 생성에 AI를 사용하지 않는다.

※ 향후 AI 도입 시, 본 문서의 Decision Ownership 원칙을 침해하지 않는 범위에서만 허용된다.

---

## 8. 준수 범위

이 원칙에 맞지 않는 구현은 수정 대상이다. SHACL 제약 위반도 마찬가지로 다룬다. 시스템 운영 기간 중 이 문서의 원칙 자체를 바꿀 일은 없다.
