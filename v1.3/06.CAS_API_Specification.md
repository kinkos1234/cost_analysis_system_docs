# 06. CAS_API_Specification

## 1. Document Purpose

CAS의 API를 정의한다. 모든 API는 08-A, 08-B 테스트를 통과해야 하고, 00~05문서의 원칙을 지켜야 한다.

구체적으로:

* 08-A, 08-B 테스트를 전부 통과할 것
* Snapshot 불변성, Stage 전환 합법성, View 일관성을 API 레벨에서 지킬 것

---

## 2. API Design Principles

### 2.1 Contract-first API

* API가 **직접 판단하는 건 없다.** 계산·평가 결과를 생성·고정·조회하는 전달자(Transport Layer)일 뿐이다.
* 계산·평가 로직은 API 바깥의 Domain Layer 책임이다.
* API는 UI 편의가 아니라 **설계 계약 집행**을 목적으로 한다.
* API는 계산/평가 결과를 수정할 수 없다.

### 2.2 Lifecycle-consistent API

* Snapshot → Calculation → Evaluation Lifecycle은 **단방향·불가역적**이다.
* API로 Lifecycle을 변경하거나, 재실행하거나, 일부만 돌릴 수 없다.

### 2.3 Context-explicit Requests

* 모든 요청은 필요한 Context를 명시해야 하며,
* Context가 불필요한 API는 **불필요한 Context를 요구하지 않는 것이 원칙**이다.

| Context    | Required    | Description             |
| ---------- | ----------- | ----------------------- |
| vehicleId  | Yes         | 차종 식별자                  |
| stageCode  | Conditional | Stage Context (조회/생성 시) |
| viewCode   | Conditional | INIT / AVG5 (분석/평가 시)   |

### 2.4 Naming Convention

API의 request/response 필드명은 **camelCase**를 표준으로 한다 (JavaScript/TypeScript 네이밍 컨벤션).

> **v1.3 변경:** Error Contract 포함 모든 API 응답 필드를 camelCase로 통일.

---

## 3. Error Contract (Global)

> Error는 API가 생성하는 것이 아니라 **Domain Rule Engine의 판단 결과를 전달**한다.
> API Error는 Transport 오류(인증, 권한, 형식)에 한정된다.

```json
{
  "errorCode": "STAGE_PREVIOUS_REQUIRED",
  "message": "설계원가 2차는 설계원가 1차 Snapshot 없이 생성할 수 없습니다.",
  "context": {
    "vehicleId": "V-A",
    "stageCode": "DC2"
  },
  "timestamp": "2024-01-15T10:30:00.000Z"
}
```

> **v1.3 변경:** Error 응답 필드를 camelCase로 통일 (`error_code` → `errorCode`).

---

## 4. Snapshot APIs

> Snapshot 생성 시점에 **Calculation과 Evaluation(INIT/AVG5)** 이 동시에 수행되고 고정된다.
> 이후 어떠한 API 호출도 Calculation/Evaluation을 재실행할 수 없다.

### 4.1 Create Snapshot

**POST** `/api/snapshots`

**Purpose:** Stage Snapshot 생성 (Atomic)

**Request Body:**

```json
{
  "vehicleId": "UUID",
  "stageCode": "DC1",
  "vehicleCost": {
    "unitPrice": 100,
    "materialCost": 60,
    "assemblyCost": 10,
    "logisticsCost": 5,
    "packagingCost": 2,
    "customsCost": 0
  },
  "partCosts": [],
  "rateOverrides": {}
}
```

> **v1.3 변경:** `customsCost` 필드 추가. `baseSnapshotId`는 서비스 레이어에서 자동 결정(직전 Stage Snapshot).

**Rules Enforced:**

* Stage Transition Legality (03 §3.2)
* Calculation Engine Rules (04)
* Snapshot Atomicity (01, 03)
* Validation Engine 검증 (10): Input Validation, Stage Transition, Snapshot Completeness
* Part → Vehicle 집계 무결성 (04 §8)

**Success (201):**

```json
{
  "snapshotId": "UUID",
  "evaluationSummary": {
    "totalTargets": 4,
    "green": 3,
    "yellow": 1,
    "red": 0,
    "requiresReport": false
  }
}
```

**Failure Cases:**

* INPUT_NULL / INPUT_NEGATIVE / PRICE_ZERO
* STAGE_PREVIOUS_REQUIRED / BASE_SNAPSHOT_INVALID
* AGGREGATION_MISMATCH — 품번 집계와 차종 서머리 불일치

---

### 4.2 Get Snapshot (Read-only)

**GET** `/api/snapshots/{snapshotId}`

**Rules:**

* Snapshot 수정/삭제 API는 제공되지 않는다.

## 5. Analysis APIs

### 5.1 Get Analysis Table (Bid vs Stage)

**GET** `/api/analysis`

**Query Params:**

* vehicleId (optional) — 차종의 모든 Snapshot 분석 데이터 조회
* snapshotId (optional) — 특정 Snapshot 분석 데이터 조회

> `vehicleId` 또는 `snapshotId` 중 하나 이상 필수.

**Response:**

```json
{
  "vehicleId": "UUID",
  "snapshotCount": 3,
  "snapshots": [
    {
      "snapshotId": "UUID",
      "stageCode": "DC1",
      "snapshotType": "STAGE",
      "calculationVersion": "1.0.0",
      "costComponents": {
        "PRICE": { "perUnitValue": "100000", "totalAmount": "..." },
        "CUSTOMS": { "perUnitValue": "0", "totalAmount": "0" }
      },
      "partCosts": [],
      "evaluations": [
        { "viewCode": "INIT", "metricCode": "COST_RATIO", "status": "GREEN" },
        { "viewCode": "INIT", "metricCode": "COST_OF_SALES_RATIO", "status": "YELLOW" }
      ]
    }
  ]
}
```

**Rules Enforced:**

* Bid Anchor 고정 (02 §5.5)
* View Context Consistency (05)

---

## 6. Evaluation APIs

> Evaluation은 Snapshot 생성 시 이미 확정된 결과를 **조회(fetch)** 하는 개념이다.
> API는 Evaluation을 실행(run)하지 않는다.

### 6.1 Get Evaluation Result

**GET** `/api/evaluations`

**Query Params:**

* vehicleId (required) — 차종별 최신 Snapshot의 평가 결과 요약

**Response:**

```json
{
  "snapshotId": "UUID",
  "stageCode": "DC1",
  "results": [
    {
      "targetId": "UUID",
      "viewCode": "INIT",
      "metricCode": "COST_OF_SALES_RATIO",
      "metricValue": "0.78",
      "targetValue": "0.80",
      "status": "GREEN"
    }
  ],
  "summary": {
    "total": 4,
    "green": 3,
    "yellow": 1,
    "red": 0,
    "requiresReport": true
  }
}
```

**Rules Enforced:**

* View-dependent Evaluation (05)
* Target immutability

**Failure:**

* SNAPSHOT_NOT_FOUND — 해당 차종에 Snapshot이 없는 경우

---

## 7. Target APIs

### 7.1 Create Target (Manager only)

**POST** `/api/targets`

**Rules:**

* Target 변경은 이후 Snapshot에만 적용
* BID Stage에는 Target 설정 불가

### 7.2 List Targets

**GET** `/api/targets`

**Query Params:**

* vehicleId (optional)
* stageCode (optional)
* viewCode (optional)
* metricCode (optional)
* isActive (optional)

### 7.3 Get Target

**GET** `/api/targets/{id}`

### 7.4 Update Target (Manager only)

**PATCH** `/api/targets/{id}`

### 7.5 Create Default Targets (Manager only)

**POST** `/api/targets/defaults`

**Request Body:**

```json
{
  "vehicleId": "UUID"
}
```

**Purpose:** 차종에 대해 2안 구조(COST_OF_SALES_RATIO 80%, COST_RATIO 100%) 기본 Target을 모든 평가 가능 Stage/View 조합에 일괄 생성

---

## 8. Reference Data APIs

### 8.1 List Reference Data

**GET** `/api/reference-data`

**Query Params:**

* referenceType (optional) — LABOR | FX
* region (optional)
* effectiveYear (optional)
* status (optional) — PENDING | APPROVED

### 8.2 Get Reference Data

**GET** `/api/reference-data/{id}`

### 8.3 Create Reference Data (Analyst+)

**POST** `/api/reference-data`

**Status:** PENDING (승인 전)

### 8.4 Update Reference Data (Analyst+)

**PATCH** `/api/reference-data/{id}`

### 8.5 Approve Reference Data (Manager only)

**POST** `/api/reference-data/{id}/approve`

## 11. 릴리스 조건

08-A, 08-B 테스트를 통과해야 릴리스 가능하다. Snapshot 생성 시 Validation Engine 검증 실패가 발생하면 API가 에러를 반환해야 한다.
