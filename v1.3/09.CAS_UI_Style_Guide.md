# 09. CAS_UI_Style_Guide

## 1. Document Purpose

CAS UI의 기준은 예쁘게 만드는 게 아니라 **잘못 읽거나 잘못 조작하기 어렵게** 만드는 것이다.

사용자가 자유롭게 탐색하도록 유도하지 않는다. 오히려 **잘못된 해석이나 판단을 하기 어려운 구조**를 만드는 데 집중한다.

관련 문서:

* 02. Information Architecture
* 05. Target & Evaluation Logic
* 07. Dashboard Feature Spec
* 08-A / 08-B Test Specifications

---

## 2. Core UI Philosophy

### 2.1 Clarity over Density

* 정보량보다 **의미 전달의 명확성**을 우선한다.
* 한 화면에서 두 개 이상의 판단 질문을 던지지 않는다.

### 2.2 Status Visibility

* 사용자는 항상 "현재 보고 있는 Stage / View / Snapshot"을 인지할 수 있어야 한다.
* 상태 정보는 스크롤 없이 확인 가능해야 한다.

### 2.3 Constraint-driven UX

* 사용자가 할 수 없는 행동은 **버튼 자체를 제공하지 않는다**.
* 경고보다 **행동 불가능 상태(disabled)** 를 우선한다.

---

## 3. Global UI Elements

### 3.1 Context Header (Mandatory)

모든 주요 화면 상단에는 고정 Context Header를 배치한다.

Displayed Fields:

* Vehicle Name
* Stage (Code + Label)
* Snapshot Timestamp
* View (INIT / AVG5)

Rules:

* Header는 스크롤 시에도 고정된다.
* Context 정보는 약어 없이 전체 표기로 제공한다.

---

### 3.2 View Toggle

Rules:

* INIT / AVG5 외 View는 존재하지 않는다.
* Toggle 변경 시 전체 화면이 즉시 재렌더링된다.
* View 혼합 표시는 허용되지 않는다.

---

## 4. Color & Visual Semantics

### 4.1 Evaluation Colors

| Status   | Color   | Usage Rule |
| -------- | ------- | ---------- |
| GREEN    | #2E7D32 | 목표 달성 강조   |
| YELLOW   | #F9A825 | 주의 상태 표시   |
| RED      | #C62828 | 즉각 조치 필요   |
| EXCLUDED | Gray    | 평가 대상 아님   |

Rules:

* 색상은 **상태 전달 목적**으로만 사용한다.
* 색상 단독 의미 전달은 금지(아이콘/텍스트 병행).

---

### 4.2 Neutral Palette

* 기본 텍스트: Dark Gray
* 보조 정보: Light Gray
* 테이블 그리드: 최소 대비

---

## 5. Typography & Numbers

### 5.1 Numeric Formatting

* 금액: 천 단위 구분자 필수
* 비율: 소수점 2~4자리 (화면별 고정)
* 단위(원, %)는 반드시 명시

---

### 5.2 Emphasis Rules

* 강조는 **굵기(Bold)** 로만 표현
* 색상+굵기 동시 강조는 RED 상태에만 허용

---

## 6. Table Design Rules

### 6.1 Bid Anchor Column

* Bid 기준 컬럼은 시각적으로 고정(frozen)한다.
* Stage 비교 테이블에서 항상 좌측에 위치

---

### 6.2 Delta Presentation

* 증감 값은 반드시 기준(Bid) 대비로 계산
* + / − 기호 명시

---

## 7. Interaction Rules

### 7.1 Read-only Enforcement

* Snapshot, Calculation, Evaluation 결과는 수정 불가
* 수정 시도 UI 제공 금지

---

### 7.2 Drill-down Consistency

* Drill-down 시 Context 유지
* Back 시 Context 손실 금지

---

## 8. Error & Empty States

### 8.1 Error Presentation

* Error는 Domain Error Code + 설명으로 표시
* 기술적 메시지 노출 금지

---

### 8.2 Empty State

* 데이터 없음 ≠ 오류
* Empty State에는 다음 Action 안내 포함

---

## 9. Accessibility & Safety

* 색상 대비 WCAG AA 준수
* 색각 이상 사용자 고려(아이콘 병행)

---

## 10. Forbidden UI Patterns

다음 UI 패턴은 CAS에서 명시적으로 금지된다.

* 자유 입력 숫자 필드 (Derived Metric 영역)
* 복수 기준 동시 비교 화면
* 계산식 노출
* Snapshot 수정/삭제 버튼

---
