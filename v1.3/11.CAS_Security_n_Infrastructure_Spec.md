# 11. CAS_Security_n_Infrastructure_Spec

> **v1.3 신규 문서:** v1.2에서 미정의였던 보안·인프라 사양을 정의. CAS의 모든 데이터 및 연산은 사내 서버에서 로컬로 처리되어야 하며, 사내 기밀 정보의 외부 유출을 방지한다.

## 1. Document Purpose

CAS의 **보안 정책, 인프라 요건, 데이터 보호, 감사 추적, 운영 절차**를 정의한다.

CAS가 다루는 데이터(수주가, 비용 구조, 목표 마진)는 **사내 핵심 기밀 정보**이다. 이 문서의 모든 규칙은 기밀 정보의 외부 유출 방지를 최우선으로 설계되었다.

---

## 2. Core Security Principles

### 2.1 On-premise Only

* CAS의 모든 구성 요소는 **사내 서버에서 로컬 실행**된다.
* 외부 클라우드 서비스(AWS, Azure, GCP 등)에 데이터를 전송하지 않는다.
* 외부 API 호출은 **금지**된다 (LLM API 포함).

### 2.2 Data Never Leaves

* 비용 데이터, Snapshot, 평가 결과는 사내 네트워크 외부로 유출되지 않는다.
* 리포트 메일 발송은 **사내 SMTP 서버**를 통해서만 수행된다.
* 브라우저 클라이언트에서 외부 CDN, 분석 서비스, 추적 스크립트를 로드하지 않는다.

### 2.3 Least Privilege

* 모든 사용자와 서비스는 **필요 최소한의 권한**만 부여받는다.
* DB 접근 계정, 시스템 계정, API 사용자 계정은 엄격히 분리한다.

## 3. Network & Infrastructure

### 3.1 Deployment Topology

```
[사내 네트워크]
  ├─ [Web Server: Next.js 15]        ← 포트: 3000
  │     ├─ SSR (App Router)
  │     └─ API Route Handlers
  ├─ [Database: PostgreSQL 17]        ← 포트: 5432
  │     └─ 로컬 디스크 영속화
  └─ [SMTP Server]                    ← 사내 메일 서버
        └─ 리포트 발송 전용
```

### 3.2 Network Isolation

* CAS 서버는 **사내 네트워크(Intranet)에만 노출**된다.
* 외부 인터넷에서의 직접 접근은 **방화벽에서 차단**한다.
* 서버 간 통신(Web ↔ DB)은 사내 네트워크 내에서만 허용한다.

### 3.3 포트 정책

| 서비스 | 포트 | 접근 범위 |
|--------|------|----------|
| Web Application | 3000 (또는 80/443) | 사내 네트워크 전체 |
| PostgreSQL | 5432 | Web Server만 접근 가능 |
| SMTP | 25/587 | Web Server만 접근 가능 |

## 4. Authentication & Authorization

### 4.1 Authentication

* **방식:** NextAuth.js Credentials Provider
* **세션:** JWT 기반, 유효 시간 8시간
* **저장:** JWT는 httpOnly, secure, sameSite=strict 쿠키에 저장
* **비밀번호:** bcrypt 해싱 (salt rounds: 12 이상)
* **로그인 실패:** 5회 연속 실패 시 계정 잠금 (30분)

### 4.2 Authorization (RBAC)

4개 역할 기반 접근 제어 (00 §5, 06 §10 참조):

| Role    | Level | Description |
|---------|-------|-------------|
| Admin   | 4     | 전체 관리      |
| Manager | 3     | 조회+승인+설정   |
| Analyst | 2     | 조회+입력+수정   |
| Viewer  | 1     | 조회 전용      |

### 4.3 Session Security

* JWT 토큰에 사용자 ID, 역할, 만료 시간만 포함 (비밀번호, 개인정보 포함 금지)
* 서버 측 JWT 서명 키는 환경 변수로 관리 (코드에 하드코딩 금지)
* 로그아웃 시 클라이언트 측 토큰 즉시 삭제

## 5. Data Protection

### 5.1 데이터 암호화

| 구간 | 암호화 방식 |
|------|----------|
| In Transit (전송 중) | TLS 1.2 이상 (HTTPS 강제) |
| At Rest (저장 시) | PostgreSQL의 pgcrypto 확장 또는 디스크 레벨 암호화 (LUKS/BitLocker) |
| 백업 데이터 | 암호화된 상태로 저장 |

### 5.2 민감 데이터 분류

| 분류 | 예시 | 보호 수준 |
|------|------|----------|
| 최고 기밀 | 수주가, 목표 마진율, 절감 목표 | 접근 로그 기록, 역할 기반 접근 |
| 기밀 | 비용 구조, 품번별 단가 | 역할 기반 접근 |
| 내부 | 차종 기본 정보, Stage 정보 | 인증 필수 |
| 시스템 | 계산 버전, 로그 | Admin 전용 |

### 5.3 금지 사항

* 비용 데이터의 CSV/Excel 대량 다운로드 기능 — v1에서는 미제공
* 브라우저 로컬 스토리지에 비용 데이터 캐싱 금지
* API 응답에 불필요한 데이터 포함 금지 (필요한 필드만 반환)
* 비밀번호, JWT 서명 키의 코드 내 하드코딩 금지

## 6. Audit Logging

### 6.1 감사 로그 대상

| 이벤트 | 기록 내용 | 보존 기간 |
|--------|----------|----------|
| 로그인/로그아웃 | 사용자 ID, 시간, IP, 성공/실패 | 1년 |
| Snapshot 생성 | 사용자 ID, vehicle_id, stage_code, 시간 | 영구 |
| Target 변경 | 사용자 ID, 변경 전/후 값, 시간 | 영구 |
| Reference Data 수정/승인 | 사용자 ID, 변경 내역, 승인자, 시간 | 영구 |
| 리포트 발송 | 발송자, 수신자, 시간, 성공/실패 | 1년 |
| 권한 변경 | 변경자, 대상자, 변경 전/후 역할, 시간 | 영구 |
| API 호출 | 사용자 ID, 엔드포인트, HTTP 메서드, 시간, 응답 코드 | 90일 |

### 6.2 감사 로그 테이블

```sql
CREATE TABLE audit_logs (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  event_type VARCHAR(50) NOT NULL,
  user_id UUID,
  target_type VARCHAR(50),
  target_id VARCHAR(255),
  action VARCHAR(50) NOT NULL,
  detail JSONB,
  ip_address VARCHAR(45),
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_audit_logs_event_type ON audit_logs(event_type);
CREATE INDEX idx_audit_logs_user_id ON audit_logs(user_id);
CREATE INDEX idx_audit_logs_created_at ON audit_logs(created_at);
```

### 6.3 감사 로그 보호

* 감사 로그는 **수정·삭제 불가** (Snapshot과 동일한 불변성 적용)
* 감사 로그 테이블에 UPDATE/DELETE 차단 Trigger 적용
* Admin도 감사 로그를 삭제할 수 없다

## 7. Backup & Recovery

### 7.1 백업 정책

| 유형 | 주기 | 보존 기간 | 방식 |
|------|------|----------|------|
| 전체 백업 (Full) | 일 1회 (야간) | 30일 | pg_dump + 암호화 |
| 증분 백업 (WAL) | 연속 | 7일 | WAL 아카이빙 |
| 스냅샷 백업 | 주 1회 | 90일 | 파일시스템 스냅샷 |

### 7.2 복구 절차

1. 장애 발생 시 최신 전체 백업 + WAL 로그로 **Point-in-Time Recovery** 수행
2. 복구 후 최근 Snapshot의 Validation Engine 검증 실행
3. 복구 완료 후 감사 로그에 복구 이벤트 기록

### 7.3 백업 저장소

* 백업 파일은 **사내 네트워크 내 별도 스토리지**에 저장
* 외부 클라우드 백업 금지
* 백업 파일 접근은 Admin + 인프라 담당자로 제한

---

## 8. Error Handling & Monitoring

### 8.1 에러 로깅

* 애플리케이션 에러는 **로컬 파일 시스템**에 기록 (외부 로깅 서비스 사용 금지)
* 에러 로그에 사용자 비밀번호, JWT 토큰 등 민감 정보 포함 금지
* 로그 파일 로테이션: 7일 보존, 이후 자동 압축 보관

### 8.2 헬스 체크

* `/api/health` 엔드포인트 제공 (인증 불필요, 내부 네트워크만)
* DB 연결 상태, 디스크 용량, 메모리 사용량 확인
* 사내 모니터링 시스템과 연동 가능

### 8.3 알림

* 시스템 장애 발생 시 사내 메일 또는 사내 메신저로 알림
* 외부 알림 서비스(PagerDuty, Slack Cloud 등) 사용 금지

## 9. Dependency Policy

### 9.1 허용되는 외부 의존성

| 의존성 | 용도 | 조건 |
|--------|------|------|
| npm 패키지 | 개발 시 | 빌드 시점에만 사용, 런타임 외부 호출 없는 패키지만 |
| Next.js 15 | 웹 프레임워크 | 텔레메트리 비활성화 필수 (`NEXT_TELEMETRY_DISABLED=1`) |
| Prisma 6 | ORM | 텔레메트리 비활성화 필수 |
| Nodemailer | 메일 발송 | 사내 SMTP 서버만 사용 |

### 9.2 금지되는 외부 의존성

* 외부 API 호출이 필요한 패키지
* 사용 통계를 외부로 전송하는 패키지 (텔레메트리)
* 외부 CDN에서 리소스를 로드하는 프론트엔드 라이브러리
* 클라우드 기반 LLM/AI API

## 10. 운영 체크리스트

### 10.1 배포 전 확인 사항

- [ ] `NEXT_TELEMETRY_DISABLED=1` 환경 변수 설정
- [ ] JWT 서명 키가 환경 변수로 설정되었는지 확인
- [ ] DB 접속 정보가 환경 변수로 설정되었는지 확인
- [ ] HTTPS(TLS) 인증서 설치 확인
- [ ] 방화벽에서 외부 접근 차단 확인
- [ ] PostgreSQL이 로컬 네트워크에서만 접근 가능한지 확인
- [ ] Snapshot Immutability Trigger 적용 확인
- [ ] 감사 로그 테이블 생성 및 Trigger 적용 확인
- [ ] 백업 스케줄 설정 확인
- [ ] SMTP 서버가 사내 서버인지 확인

### 10.2 정기 점검 사항 (월 1회)

- [ ] 감사 로그 정상 기록 확인
- [ ] 백업 정상 수행 및 복구 테스트
- [ ] 디스크 용량 확인 (80% 이상 시 알림)
- [ ] 비활성 사용자 계정 점검
- [ ] SSL 인증서 만료일 확인

## 11. 변경 시 주의

보안 정책 변경은 반드시 관리자 승인을 거친다. 특히 네트워크 정책, 데이터 보호 수준, 감사 로그 정책 변경은 전사 보안 정책과의 정합성을 먼저 확인한다.
